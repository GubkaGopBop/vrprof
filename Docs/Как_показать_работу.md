# Демонстрация и объяснение работы

## Быстро показать результат без Unity

1. Распаковать архив целиком. Нужна Java 17 или новее. В комплекте уже есть собранный JAR и Gson.
2. Открыть PowerShell в `JavaAnalyzer`.
3. Выполнить одной строкой:

```powershell
java -Dfile.encoding=UTF-8 -jar build/vrprof-analyzer.jar examples/completed.json results/show-completed
```

4. Открыть `results/show-completed/summary.txt`. Программа должна показать 9 из 9 шагов, одну подсказку и одну ошибку. В JSON есть описание события № 6: вместо модуля B выбран модуль A.
5. Повторить с `examples/incomplete.json` и каталогом `results/show-incomplete`. Результат — 4 из 9, ноль подсказок, одна ошибка. Завершение самой программы успешно, хотя проба не завершена: это разные признаки.
6. Для проверки ошибки сделать копию входного файла и поставить `Difficulty: 0`. Программа должна сообщить об ошибке и завершиться с кодом 1. Исходные проверенные примеры менять не нужно.

Если JAR требуется собрать заново, выполнить `./build.ps1` из `JavaAnalyzer`; нужен JDK, а не только runtime. Для всех интеграционных проверок из корня проекта выполнить `python Verification/verify.py`; дополнительно нужен .NET SDK 8. Протокол находится в `JavaAnalyzer/results/verification.json`.

## Показать сцену и экспорт Unity

Открыть проект в Unity 6000.3.9f1, дождаться импорта и открыть `Assets/Scenes/PcTrial.unity`. В Play Mode выполнить первые четыре действия, запросить подсказку, выбрать сначала A, затем B и завершить остальные шаги. После заполнения отзывов сохранить журнал. Путь показывает интерфейс. Коды участников задаются у контроллера в Inspector до запуска. Файл можно передать Java-компоненту вместо контрольного примера.

Для автоматической проверки экспорта есть меню `Tools > VrProf > Экспортировать проверочные журналы`. Эта команда реально вызывает компонент и сохранение в Editor, но её нельзя описывать как ручное прохождение или проверку на VR-шлеме. Сцена моделирует порядок замены RAM; физическую диагностику компьютера программа не выполняет.

## Что объяснить на защите

Два алгоритма решают задачи наставника: восстановить последовательность действий и получить краткую сводку. Процедурная версия хранит алгоритмы в статических функциях C#. Java-версия организует ту же обработку в объектах. `UnityJsonAttemptReader` читает файл, `AttemptEvaluator` проверяет шаги, `TextSummaryFormatter` формирует текст, а `TrialAnalyzer` связывает эти операции. `Main` занимается запуском и файлами результата.

`record` — класс для данных: поля закрытые и неизменяемые, методы доступа создаются языком. Конструктор может проверять значения. `List.copyOf` не позволяет изменить список событий после создания попытки. Это не искусственное наследование: программа использует включение данных и интерфейсы там, где есть заменяемая ответственность.

При событии выбора A алгоритм сравнивает действие и объект с очередным шагом, который ожидает B. Счётчик выполненных шагов остаётся прежним, а ошибка добавляется в список. Следующее правильное событие может продвинуть попытку. Подсказка учитывается отдельно и не выполняет шаг за школьника.

Интерфейс `SummaryFormatter` позволяет выбрать другой способ представления результата без изменения проверки. Само наличие интерфейса не ускоряет программу. Один проход по n событиям занимает O(n), если коды короткие; весь JSON дополнительно хранится в памяти. В Unity пересчёт всего журнала после каждого нажатия может дать O(n²) за полную попытку.

Поле Summary из входа игнорируется: Java пересчитывает сводку. Проверки сравнили реальные результаты Java, C# и сохранённый Unity-текст. Поэтому результат подтверждён выполнением кода. Однако это не доказывает педагогическую эффективность и не заменяет студенческое взаимное рецензирование.
