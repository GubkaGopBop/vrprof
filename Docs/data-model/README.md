# Расширение модели по замечаниям преподавателя

Модель содержит ровно 10 сущностей: роль, участник, задание, учебный объект, шаг задания, правило проверки, попытка, событие, отзыв, результат попытки. В ER-модели два листа: состав сценария и данные прохождения. Между листами `attempt.exercise_id` ссылается на задание, а `event.actual_object_id` — на учебный объект. Это одна модель; дополнительных не связанных моделей нет.

Кратности обозначены на концах связей. Соединения идут горизонтально и вертикально с поворотами на 90 градусов, легенда удалена по указанию автора. Связь попытки и отзывов дополнительно ограничена максимумом два и уникальностью автора внутри попытки. Эти связи не задают направление выполнения алгоритма. Направленные стрелки используются в блок-схемах.

`ten-entity-example.json` — проверяемое логическое представление фактически сохранённого Unity-журнала `JavaAnalyzer/examples/completed.json`. Сценарий и правила извлечены из текущего `TrialLogic.cs`, результат взят из запуска Java, совпавшего с C#. Имена участников и отзывы остаются условными учебными данными. Физическая база данных этим преобразованием не создаётся.

`schema.json` содержит поля десяти сущностей. `trace.json` показывает попытку, ученика и наставника, событие № 6, фактический модуль A, ожидаемый модуль B, правило, результат и отзыв наставника. `mapping-check.json` подтверждает проверку 13 связей внешних ключей. Дополнительно проверяются уникальность идентификаторов, нумерация событий, один автор каждой роли и диапазоны оценок.

Повторить построение и проверку из корня проекта:

```powershell
python Verification/model_mapping.py
dotnet run --project Verification/TeacherCases -- Docs/data-model/teacher-cases.json
```

Для второй команды нужен .NET SDK 8. Проект компилирует настоящий `Assets/Scripts/TrialLogic.cs`. Пять целевых проверок: одинаковое действие с другим объектом; исправление выбора после ошибки; действие после 9/9 шагов; совпавшее, но неуспешное действие; подсказка после завершения. Два последних случая уточняют границы схемы: подсказка обрабатывается до проверки очередного шага, а `Success=false` не засчитывается.

При дополнительном действии после завершения возвращается `completed=true`, `completedSteps=9`, `errors=1`. Это не сброс попытки и не исключение индекса: левая часть условия `CompletedSteps < steps.Count` предотвращает чтение `steps[9]`.

При развитии хранилища событие сохраняет собственный идентификатор, номер и связь с попыткой. Ошибка не удаляет событие. Отзыв связывается с попыткой и автором; повторная правка отзыва обновляет ту же запись. Для попытки хранится один актуальный вычисленный результат, который обновляется после пересчёта. История версий результатов в эту модель не включена.
